# P4 - Knowledge-management specialist (round 2, on the R1 build)

## Verdict

The connection is now a round trip. An item names its intake note, the note names its radar record (`radar_id` and `radar_url`), and the `ingested` flag is read back from the note instead of being written once and forgotten. The two fields that were declared and never filled are gone from the contract, and the profile says who fills them instead. Rewriting a note is now one command away from the reader's own work, because `apply_actions.py --notes` refreshes the notes with the marks. What is left is small: a rewritten note still leaves no history in the vault, and the theme names travel only as one comma-joined field.

## Findings

| # | Sever | Feature | Finding | Evidence | Fix |
|---|---|---|---|---|---|
| 1 | S2 | F18 | A rewrite replaces the note in place. The vault is not under version control, and the note itself records no change. | `vault_notes.py --rewrite` writes the same file name. | Add `radar_updated` and a one-line change note, so a reader can see the note moved on. |
| 2 | S3 | F17 | The back-link points at the item file in the repository, not at the radar page. A wiki reader who is not a programmer gets a JSON file. | `radar_url` points to `blob/main/data/items/<id>.json`. | Add the published page link as a second field, or point `radar_url` at the site with the id as a fragment. |
| 3 | S3 | F19 | `radar_theme_names` is one string of names. A pipeline that wants them as a list must split on commas, and a name with a comma would break. | `note_text` writes `radar_theme_names: "a, b"`. | Write the names as a quoted list, as the tags line already does. |

## What would change my mind

Nothing blocks me. The contract is now honest about what it fills, the link exists in both directions, and the flag is read. Finding 1 is the only one I would press, and it is a one-line change.
